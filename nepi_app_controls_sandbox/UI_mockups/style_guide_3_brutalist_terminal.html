Brutalist Terminal

No color, no curve, no ambiguity. Everything is set in monospace on pure white with pure black rules, as if the entire RUI were a well-formatted terminal session. One red accent exists for exactly one purpose: things that are broken or destructive.

PRINCIPLE

This guide is the opposite instinct from a dashboard: it does not try to look friendly, calm, or "designed" at all. Grids are drawn with real 2–4px black rules, type is exclusively monospaced, and there is exactly one non-black/white color in the entire system — reserved for the two things in this app that the README documents as broken (Trigger, FloatSliders). If a NEPI engineer already lives in a terminal all day, this guide argues the RUI should not fight that mental model, and every value on screen should be exactly as legible and unambiguous as a `cat` of a status topic.

RULES

— Monospace only. No secondary typeface exists in this system.
— Rules are always 2–4px solid black, drawn as literal grid lines between cells, never a soft border.
— Zero border-radius, zero shadow, zero gradient, anywhere.
— The single accent color marks broken or destructive items exclusively — never used for emphasis or branding.
— Labels for control identifiers echo the actual Python dict key (demo_float_slider) alongside the display name, since this guide assumes an engineer audience comfortable reading source.
Brutalist Terminal covers the same 18 demo fields (10 controls + 8 data) as the real app. See concept_3_brutalist_terminal.html for the full page layout and UI_mockups/README.md for rationale.
